# Atoll: local data, permissions, trust boundaries, and performance

Static source review at commit `b8d86a2d8118d905ffa3e2c912adc736683741bb`. No application, source code, build/test scripts, exploit, or helper was executed. Findings describe the reviewed source, not a verified release binary or measured runtime. Network/provider-specific review is in the other audit notes.

## Security findings

### High: local extension RPC grants itself access without user approval

`ExtensionRPCServer.swift:386–397` takes the connection identity from client-supplied `params.bundleIdentifier`. `ExtensionRPCService.swift:139–158` then automatically authorizes the requested identity whenever it is not already authorized; it does not preserve denial/revocation. `ExtensionAuthorizationManager.swift:212–214` initially grants every scope. Extensions and file sharing default to enabled (`Constants.swift:1381–1394`), and the listeners start unconditionally at launch (`DynamicIslandApp.swift:707–710`).

Consequences are concrete: an untrusted local client can self-authorize, list shelf names/paths/text (`ExtensionRPCService.swift:382–419`), and read file contents as base64 (`422–456`). It can also add a caller-chosen existing path (`540–559`) before reading that new shelf item, so the interface is not limited to files the user originally placed on the shelf. Reads remain limited by the host app's filesystem/TCC access; this is not a claim of bypassing every macOS protection. XPC also auto-authorizes pending clients (`ExtensionXPCService.swift:45–64`), though it derives bundle identity from the connecting process instead of the RPC body (`ExtensionXPCServiceHost.swift:125–134`). XPC identity is not code-signature authentication.

The RPC listener **is correctly bound and peer-checked to loopback** (`ExtensionRPCServer.swift:85–115,271–280`). Do not describe the current commit as exposing this port to the LAN. Browser-origin access was not exercised; the confirmed threat is an arbitrary local client, with no secret or user-consent boundary in this code path.

Recommendation: no extension listener in the personal baseline. If extensions are added later, require explicit per-client authorization, bind grants to an authenticated client rather than a bundle-name string, preserve denials, separate file scopes, and require item-specific user approval. Remove arbitrary-path import from the RPC API. Add connection/message/byte limits before JSON/base64 decoding; `receiveMessage`/`processMessage` (`345–399`) and shelf export currently lack an application-level payload cap.

### High: extension upload filename is not confined to its temporary directory

`ExtensionRPCService.swift:568–577` decodes caller-supplied data, appends caller-supplied `fileName` to `temporaryDirectory/AtollExtensionFiles`, and writes it. There is no basename restriction, standardized containment check, generated per-upload identifier, or collision policy. Path components such as `..` can escape the intended directory; repeated names can overwrite existing uploads. Combined with self-authorization, this gives a local client an app-privileged write primitive, subject to normal macOS filesystem/TCC access. Static finding; no payload was executed.

Recommendation: generate a unique destination name inside a private owned directory; preserve a sanitized display name separately. Reject separators/dot components, reject symlinks, enforce byte limits, and create files without overwriting. Apply the same ownership checks to cleanup. [Source](https://github.com/Ebullioscopic/Atoll/blob/b8d86a2d8118d905ffa3e2c912adc736683741bb/DynamicIsland/services/Extensions/ExtensionRPCService.swift#L540-L587).

### Hardening context, not evidence of malicious behavior

Both Debug and Release have App Sandbox disabled and hardened runtime enabled (`project.pbxproj:791–792,866–867`). The app entitlements explicitly disable library validation (`DynamicIsland.entitlements:5–6`), even though the project runtime-exception flag says NO (`project.pbxproj:840,915`); the signed binary would need inspection to establish effective entitlements. This increases the importance of fixing extension boundaries. There is no `get-task-allow` entitlement in the reviewed entitlements file. Camera, calendar, Apple Events, and XPC-related entitlements reflect features, not automatic OS consent.

For our app: keep hardened runtime, avoid disabling library validation, request only the permissions needed by selected features, and use Apple frameworks so no embedded media adapter is required. App Sandbox is a separate compatibility decision; simply saying an unsandboxed app is malware would be unsupported. [Entitlements](https://github.com/Ebullioscopic/Atoll/blob/b8d86a2d8118d905ffa3e2c912adc736683741bb/DynamicIsland/DynamicIsland.entitlements#L5-L27), [Release settings](https://github.com/Ebullioscopic/Atoll/blob/b8d86a2d8118d905ffa3e2c912adc736683741bb/DynamicIsland.xcodeproj/project.pbxproj#L857-L915).

## Privacy and retention tradeoffs

- **Clipboard:** feature and persistence default ON, history size defaults to 3 (`Constants.swift:1359–1364`); monitoring starts when clipboard UI/shortcut/settings starts it, not automatically from `ClipboardManager.init`. Once started it polls every 0.5 seconds (`ClipboardManager.swift:374–380`). Text/URLs/file paths/RTF history and pinned items are encoded into UserDefaults (`756–795`); images are written to `~/Documents/ClipboardData` (`77–106,248–255`). The capture path (`576–674`) has no visible concealed/transient-pasteboard marker or source-app exclusion before reading strings/images. Sensitive copies can therefore become ordinary history while monitoring is active. No age-based expiry is implemented here, only count-based eviction/manual removal. This is local collection, not evidence that Atoll uploads clipboard history; Documents contents may separately enter system backups or cloud folder sync depending on the user's settings, which were not inspected.
- **Positive clipboard changes:** turning persistence OFF removes saved unpinned history and its images, including at launch (`269–365`; `DynamicIslandApp.swift:756–758`). Pinning deliberately persists an item even with history persistence off (`483–507`), which the settings explain. Do not report the older bug that session-only images are always written to Documents; this commit now keeps them in memory.
- **Screenshot retention gap:** Screen Assistant creates screenshots in `~/Documents/ScreenAssistantScreenshots` (`ScreenAssistantManager.swift:140–149`; `ScreenshotSnippingTool.swift:146–168`). `removeFile`/`clearAllFiles` only delete audio backing files (`ScreenAssistantManager.swift:256–278`); clearing attachments does not delete app-generated screenshots. Attachment metadata is saved under `ScreenAssistantFiles` in UserDefaults (`343–357`). Voice recordings use `~/Documents/ScreenAssistantAudio` (`129–138`) and are deleted on attachment removal. No screenshot expiry/sweep was found in these paths. This directly differs from the user's temporary-container requirement.
- **Clipboard drag leftovers:** persisted clipboard images are copied to the system temporary directory before dragging (`ClipboardDragging.swift:77–87`), protecting against history eviction during drag. No cleanup for those copies was found. OS temporary purging is not a deletion deadline. Our exporter needs owned-file leases, explicit retention, and next-launch cleanup.
- **Lock screen disclosure:** media, reminder, weather and other lock-screen widgets default ON (`Constants.swift:1094–1099`); calendar-event display also defaults ON with calendar selection `all` (`1153–1155`). Reminder titles are rendered while locked (`LockScreenReminderWidgetManager.swift:57–72`; `LockScreenReminderWidget.swift:40`). The window is intentionally delegated and shown at shielding level (`LockScreenReminderWidgetPanelManager.swift:87–118`). This is an intentional feature, but private event/reminder titles may be visible to someone near the locked Mac after the relevant permissions/content are available. Our default should hide sensitive titles/previews while locked, with per-feature opt-in to expose them.
- **Calendar/Reminders:** full-access EventKit requests are separate (`CalendarManager.swift:155–199`; `CalendarServiceProviding.swift:45–61`). Atoll also saves reminder completion (`CalendarServiceProviding.swift:125–139`); do not describe its whole calendar/reminder module as read-only. Event list display is local in the reviewed paths. Our requested agenda can remain display-only while accurately explaining that Apple grants full calendar access for reading.
- **Status versus recording:** default-on camera/microphone indicators read device-running properties (`CameraMonitor.swift:222–306`; `MicrophoneMonitor.swift:255–304`), not audio/video samples. Screen-recording detection uses CGS status notifications and app activation, not continuous screenshot capture (`ScreenRecordingManager.swift:23–39,375–412`). Mirror camera preview defaults OFF (`Constants.swift:1022`), real-time audio capture OFF (`1064`), per-app volume OFF (`1341`). Do not imply the default privacy indicators secretly record camera/mic content. Screen Assistant voice recording is a separate user action.

## Functional and performance observations

1. **Session-only clipboard image dragging loses its image.** With persistence OFF, new images have no `imageFileName` (`ClipboardManager.swift:86–92`), but `imageDragProvider` requires `imageFileURL` (`ClipboardDragging.swift:24–27,80–81`). `dragItemProvider` then falls back to preview text (`63–74`). Copy-back can still use `getImageData` (`ClipboardManager.swift:137–141`). Implement an in-memory representation plus temporary export/file promise rather than depending on a persistent filename. This is static functional evidence, not an app compatibility test.
2. **Bound clipboard bytes, not just item count.** Clipboard collection reads whole Finder image files and image representations on the polling/UI path, and dedup repeatedly reads images (`ClipboardManager.swift:581–610,725–729`). HTML-to-RTF import invokes WebKit on the main thread (`799–820`). Default count 3 reduces normal load but does not cap an individual large image. Our app should encode once, hash for dedup, bound total/individual bytes, cache small previews, avoid background HTML import, and keep I/O off the UI thread where APIs permit.
3. **Useful stats lifecycle already exists.** Stats defaults OFF, interval 1 second, stop-after-close ON (`Constants.swift:1282,1291–1292`). The manager activates for the visible stats tab and stops 3 seconds after closing (`StatsManager.swift:514–546`), caps update settings at 1–60 seconds (`611–646`), and caches top-process samples at 2 seconds (`455–460`). Metrics include interface/IP/device names and process names, not packet capture (`StatsManager.swift:1032–1214` and process section). For the user's accepted stats feature, preserve visibility gating, bound retained process metadata, and use a slower idle cadence. No benchmark was run.
4. **Calendar background work can be gated better.** `CalendarManager` starts a 60-second refresh loop once created (`63–69,347–357`); after calendar consent it refreshes lock-screen events even if the user is unlocked or the lock-screen event widget is disabled. An all-time lookahead fetch can span 365 days (`307–321`). Refresh on event-store changes plus the next relevant event boundary, and fetch only selected calendars/current horizon. Existing throttles/coalescing (`48–57,90–124`) are positive.
5. **Connection monitoring is mainly event-driven, but collects local identities.** `NetworkConnectivityManager.swift:62–89` uses NWPathMonitor/CoreWLAN, retaining SSID in memory; its privacy-redacted SSID fallback invokes `networksetup` with a 1-second timeout and 1.5-second cache (`248–298`). Bluetooth adds a 3-second paired-device fallback poll (`BluetoothAudioManager.swift:252–280`), a cached profiler snapshot (`77–95`), and, if enabled, a filtered `log stream` (`230–248,2187–2198`). Avoid shell fallbacks unless requested; use notifications, suspend disabled features, and throttle expensive metadata collection. Do not call these paths internet uploads.
6. **Focus detection has a permission tradeoff.** Default Focus detection ON with `withoutDevTools` mode (`Constants.swift:1476–1477`); this mode selects assertions polling, which checks Full Disk Access and runs every 2 seconds (`DoNotDisturbManager.swift:524–535,584–604`). The alternative DevTools/log-stream mode can query recent `duetexpertd` logs (`538–578`). Keep the user's accepted status feature, but do not make Full Disk Access a prerequisite for the whole app; explain optional access, degrade to an unavailable state when denied, and evaluate narrower alternatives.
7. **Recording stop control is broader than a status indicator.** On an explicit stop request it sends System Events/CGEvent shortcuts and can signal all matching `screencapture` processes (`ScreenRecordingManager.swift:116–158,336–370`). Keep this out of the baseline; if added later, identify the recording session and expose the extra automation/accessibility requirements. Default recording detection ON does not itself mean these kill operations run automatically.
8. **Terminal is optional and powerful by design.** It defaults OFF with `/bin/zsh` and bounded 1000-line scrollback (`Constants.swift:1301–1310`); enabling it launches a local shell under the user's identity through SwiftTerm (`TerminalManager.swift`). Treat it as a separate power-user feature, unnecessary for the requested island; no automatic malicious command was found in the reviewed path.

## Updates, helpers, and build trust

Sparkle is configured with an Ed25519 public key and HTTPS feed (`Info.plist:16–23`); stable appcast enclosures carry `sparkle:edSignature` (`Updates/appcast.xml:11` and subsequent releases). Stable is the default update channel (`Constants.swift:986`), while beta/alpha/nightly map to distinct feeds (`UpdateChannel.swift:52–59`). Users can toggle automatic checks/downloads (`SoftwareUpdater.swift:55–74`). These are useful controls, not proof that a downloaded binary matches reviewed source. No release signature, notarization, dependency binary, or updater behavior was executed/verified.

The Xcode archive postprocess only re-signs bundled Sparkle XPC services/framework on Release install (`project.pbxproj:502`); it does not itself download/run a remote shell script. Runtime helper execution is primarily fixed Apple tools with argument arrays in the reviewed modules. Repository `scripts/test_claude_keychain.sh` compiles/runs a credential-related test; it was read only and deliberately not run. A later build should audit resolved packages and any prebuilt framework separately. For our personal app, default to user-triggered local rebuilds and no updater/helper/listener; add distribution trust machinery only if distribution is actually requested.

## What to carry into the user's app

Keep the user's requested screenshot/file shelf, actual music players, calendar, and all accepted extras, including clipboard history, stats, lock-screen widgets, visualizer, status indicators, and timers. Apply the findings to their defaults and implementation: clipboard collection is explicit, persistence/expiry are user-controlled, sensitive lock-screen titles require opt-in, live audio capture asks for its own permission, collectors stop when disabled or unneeded, and basic functions keep working when optional access is denied. External extension APIs, shell, and AI account access are separate unrequested surfaces and can remain excluded. Keep screenshot bytes in memory with owned temporary compatibility exports, define automatic cleanup honestly across quit/relaunch, authenticate any later local integration, and measure idle CPU/memory on both actual displays.
