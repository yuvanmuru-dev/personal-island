# DynamicNotch source security, privacy, and efficiency review

Reviewed for a personal Mac customization build, 2026-11-10. Snapshot: `jackson-storm/DynamicNotch` commit `f8623de5806ec5a22d9845189360bc9f4d92c374`.

Scope: broad static searches across the supplied app text (495 files under `DynamicNotch`, including 57,832 Swift lines), followed by manual inspection of networking, initialization, permissions, screenshots, tray persistence, FaceID, media helpers, download readers, system bridges, and build/install scripts. This is not a line-by-line verification of every UI file. No repository program, build, installer, helper, or app was executed. No user's calendars, clipboard, browsing databases, screen contents, passwords, or other personal records were read. Embedded executables/framework implementations, third-party dependency implementations, runtime traffic, effective signing/entitlements, performance, and macOS 27 behavior remain untested. A source-only acquisition is not a buildable or verified binary distribution.

## Principal findings

### DN-01 — High: optional webcam unlock does not authenticate an enrolled identity

This is an additional feature outside the user's requested utility list and should be removed from a fork, rather than inherited accidentally.

- The setup view verifies the actual local Mac account password and saves it: [FaceIDSettingsView.swift L314-L335](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/FaceID/Settings/FaceIDSettingsView.swift#L314-L335). The helper uses OpenDirectory `record.verifyPassword`, then stores UTF-8 password data in a generic Keychain item with `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`; no per-use biometric access-control object is installed in this query: [FaceIDKeychainService.swift L14-L63](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/FaceID/Services/FaceIDKeychainService.swift#L14-L63).
- Enrollment persistence is a Boolean and date string: [FaceIDSettingsStore.swift L64-L74](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/FaceID/Services/FaceIDSettingsStore.swift#L64-L74). The recognition path uses Vision face landmarks; checks centering, face size, eyes, facing, and gaze; accumulates progress; and reports success. It does not compare an enrolled face representation or identity: [FaceIDService.swift L262-L299](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/FaceID/Services/FaceIDService.swift#L262-L299).
- A missing physical camera calls `simulateFallbackScan()` from the ordinary setup path, and that fallback reports success after two delays: [L121-L125](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/FaceID/Services/FaceIDService.swift#L121-L125), [L205-L212](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/FaceID/Services/FaceIDService.swift#L205-L212). The test-only early fallback is separate at L82-L85; the missing-camera fallback is not guarded by that test condition.
- A successful lock-screen scan invokes `unlockWithSavedPassword`: [LockScreenFaceIDWindowManager.swift L300-L309](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/LockScreen/Windowing/LockScreenFaceIDWindowManager.swift#L300-L309). The implementation retrieves the password and posts its characters and Return as global HID keyboard events after a 150 ms delay, without verifying the target password field immediately before posting: [FaceIDService.swift L216-L257](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/FaceID/Services/FaceIDService.swift#L216-L257).

Conditions matter: `isFaceIDEnabled` defaults true but `isEnrolled` defaults false; the wake trigger requires a lock presentation, enabled feature, enrollment, and unlock-on-wake, and the button presentation requires locked + enabled + enrolled. The password injection function also requires a stored nonempty password. Thus this is a serious conditional authentication design problem after setup, not evidence that an untouched install automatically unlocks a Mac. Actual event delivery across macOS lock-screen protections was not attempted. This is not Apple's hardware biometric authentication API. Evidence: [settings L11-L35](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/FaceID/Services/FaceIDSettingsStore.swift#L11-L35), [trigger L165-L198](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/LockScreen/Windowing/LockScreenFaceIDWindowManager.swift#L165-L198).

Action: exclude webcam unlock and password enrollment from the personal app. Preserve cosmetic lock-screen widgets separately. Do not collect or store the user's login password.

### DN-02 — High conditional data-loss risk: orphan tray cleanup cannot distinguish copies from moved originals

The default tray import mode is copy, which limits ordinary exposure: [MediaAndFilesSettingsStore.swift L49-L53](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/Settings/Shared/Stores/MediaAndFilesSettingsStore.swift#L49-L53). An optional move-originals mode first moves source items into `~/Library/Application Support/DynamicNotch/FileTray`, then registers/persists them: [FileTrayViewModel.swift L176-L184](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/DragAndDrop/Tray/ViewModels/FileTrayViewModel.swift#L176-L184), [L396-L409](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/DragAndDrop/Tray/ViewModels/FileTrayViewModel.swift#L396-L409).

On initialization it restores its UserDefaults manifest then removes every untracked item in the storage directory. A missing or undecodable manifest yields no retained items; decode failure removes the manifest key. Orphan cleanup calls permanent `removeItem`, not Trash, regardless of whether an orphan was a moved original: [L127-L130](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/DragAndDrop/Tray/ViewModels/FileTrayViewModel.swift#L127-L130), [L273-L319](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/DragAndDrop/Tray/ViewModels/FileTrayViewModel.swift#L273-L319), [L324-L365](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/DragAndDrop/Tray/ViewModels/FileTrayViewModel.swift#L324-L365).

A crash after a move but before manifest persistence, partial failed multi-item import, or registry loss/corruption can therefore produce untracked original files that are deleted at next initialization. This consequence follows from the source; no destructive reproduction was run. Normal explicit removal correctly distinguishes delete-copy versus trash-moved-original (L260-L267), but orphan cleanup lacks that knowledge.

Action: default to original-file references or owned copies; use transactional durable ownership records; quarantine unknown files instead of deleting them; enforce size/count quotas; provide explicit removal semantics. Do not transplant startup cleanup unchanged.

### DN-03 — Screenshot behavior conflicts with the requested temporary container

Monitoring changes the global `com.apple.screencapture` save location to a cache staging directory, optionally disables Apple's floating thumbnail, and scans every 0.25 seconds: [ScreenshotMonitorService.swift L29-L67](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/ScreenshotHub/Services/ScreenshotMonitorService.swift#L29-L67). Preference writes and `killall SystemUIServer` are at [L280-L315](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/ScreenshotHub/Services/ScreenshotMonitorService.swift#L280-L315). Stop restores the captured location, but there is no crash recovery guarantee. Thumbnail handling writes true on feature disable rather than restoring the user's prior value: [NotchScreenshotEventsHandler.swift L97-L120](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/ScreenshotHub/EventHandlers/NotchScreenshotEventsHandler.swift#L97-L120).

`ScreenshotViewModel` retains one active screenshot. Ordinary dismissal calls save-to-disk; hiding the screenshot presentation also triggers saving. A drag is marked dropped at drag start, then dismisses shortly afterwards, and dropped/copied temporary sources are deleted after another 0.5 seconds: [ScreenshotViewModel.swift L221-L267](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/ScreenshotHub/ViewModels/ScreenshotViewModel.swift#L221-L267), [ScreenshotNotchView.swift L61-L67](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/ScreenshotHub/Views/ScreenshotNotchView.swift#L61-L67), [save observer L125-L135](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/ScreenshotHub/EventHandlers/NotchScreenshotEventsHandler.swift#L125-L135). This does not prove successful transfer or that the receiver has finished reading. It can lose the tray item after a canceled drag or remove a source before a slow consumer finishes.

OCR uses Apple's Vision locally in the inspected implementation, with no network call in that service: [OCRService.swift L9-L42](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/ScreenshotHub/Services/OCRService.swift#L9-L42). That is a favorable observation, not a system-wide data-sharing guarantee.

Action: replace capture/lifetime policy with a dedicated capture command and shared multi-item shelf. Keep source/export leases through receiver consumption and grace periods, do not infer upload success from drag completion, and make Save explicit. Use recovery cleanup limited to demonstrably app-owned temporary exports.

### DN-04 — Undisclosed-by-control external IP lookups and lyrics sharing need explicit policy

The VPN view model calls `fetchLocation()` when a new active VPN UUID appears (including refresh of an existing active VPN during initialization). `fetchLocation()` has a concurrency guard, not an opt-in guard: [VpnViewModel.swift L246-L277](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/Network/VPN/ViewModels/VpnViewModel.swift#L246-L277). It tries HTTPS `api.country.is`, then `ipapi.co/json/`, then `ipwho.is/`; the session is ephemeral and time-limited: [VPNLocationService.swift L20-L107](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/Network/VPN/Services/VPNLocationService.swift#L20-L107). These services see the request's source IP and timing. There is no evidence here that screenshots or passwords are included in these requests. The resulting public IP need not prove which VPN tunnel carried the request; no tunnel binding is shown.

Normal `AppContainer` explicitly injects LRCLIB alone: [AppContainer.swift L85-L95](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Application/AppContainer.swift#L85-L95). It sends title and artist, with optional album/duration, in HTTPS query parameters: [LRCLIBLyricsProvider.swift L123-L147](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/NowPlaying/Services/Lyrics/Provider/LRCLIBLyricsProvider.swift#L123-L147). Lyrics requests begin when a lyrics presentation is active, rather than continuously on every track: [NowPlayingViewModel.swift L299-L315](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/NowPlaying/ViewModels/NowPlayingViewModel.swift#L299-L315). Lock-screen lyrics default true in [GeneralSettingsStorage.swift L217](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Core/SettingsEngine/GeneralSettingsStorage.swift#L217).

An alternate/default view-model initializer constructs a LRCLIB + Lyrics.ovh composite, and the OVH implementation sends artist/title in its path, but normal injection above overrides that default. Do not claim OVH traffic necessarily occurs in the ordinary app: [NowPlayingViewModel.swift L73-L86](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/NowPlaying/ViewModels/NowPlayingViewModel.swift#L73-L86), [OvhLyricsProvider.swift L33-L59](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/NowPlaying/Services/Lyrics/Provider/OvhLyricsProvider.swift#L33-L59).

`requestInternetAccess()` is only an availability test, not a consent prompt: [NotchEventCoordinator.swift L297-L304](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/Notch/NotchEventCoordinator.swift#L297-L304).

Action: outbound connections disabled by default in the personal build; separate toggles for lyrics, VPN public-IP/country lookup, and artwork. Explain the exact data sent beside each setting. Local VPN status does not require country lookup. Replace default URLSession caching for listening metadata with an ephemeral, bounded in-memory cache if enabled.

### DN-05 — Upstream update control must be removed or replaced in a personal fork

The app retains the original author's GitHub raw `main/appcast.xml` feed and EdDSA key: [Info.plist L11-L16](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Application/Info.plist#L11-L16). Sparkle starts during initialization, configures a ten-minute interval, and also adds launch/periodic checks gated on Sparkle's automatically-checks setting: [SparkleUpdater.swift L26-L104](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/SoftwareUpdate/Services/SparkleUpdater.swift#L26-L104). The published property starts false, but reflects Sparkle state later; this review does not establish first-install consent/default behavior from Sparkle's own code.

The configured signature key is a positive control; no signature-bypass code was identified in the reviewed app wrapper. However, keeping the original feed/key delegates future executable updates to upstream and can replace a custom build with their release if an update is accepted. Action: remove Sparkle and its settings/feed/key from the initial personal fork, and build updates manually from reviewed pinned source.

### DN-06 — Broad privileges and private integrations require isolation, not a blanket malware label

The project sets `ENABLE_APP_SANDBOX = NO` and hardened runtime true for both configurations: [project.pbxproj L570-L580](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch.xcodeproj/project.pbxproj#L570-L580), [L635-L645](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch.xcodeproj/project.pbxproj#L635-L645). ### DN-07 — Default window-margin feature can manipulate unrelated app windows

The notchless margin setting defaults true: [ApplicationSettingsStore.swift L154-L162](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/Settings/Application/Stores/ApplicationSettingsStore.swift#L154-L162). The constrainer starts on ordinary app launch, registers running applications, adds a global mouse event tap, and constrains visible windows once Accessibility access exists: [AppDelegate.swift L72-L79](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Application/AppDelegate/AppDelegate.swift#L72-L79), [NotchlessWindowConstrainer.swift L102-L115](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/Notch/Services/NotchlessWindowConstrainer.swift#L102-L115), [L261-L288](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/Notch/Services/NotchlessWindowConstrainer.swift#L261-L288).

This is a deliberate feature, not evidence of a keylogger. It expands the authority of the floating-capsule implementation and may surprise a user who only wants an overlay on the Dell. Action: default off; explain window resizing; avoid running the observer/event tap at all unless explicitly enabled.

## Efficiency recommendations backed by source observations

- Replace the 0.25 s screenshot-directory scan with direct capture delivery and file events only for optional external imports. Lazy decoding of full images and a maximum 1024-pixel preview already avoid an unnecessary full screenshot decode: [ScreenshotImageLoader.swift L5-L32](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/ScreenshotHub/Services/ScreenshotImageLoader.swift#L5-L32). Retain that preview/full separation.
- Avoid duplicate connectivity monitors. `AppContainer` creates separate Wi-Fi and VPN view models (L74-L75); the VPN convenience initializer constructs its own `WifiMonitor` (L81-L85), which owns a `NWPathMonitor` and writes the shared `CWWiFiClient` delegate (L40-L51). Share a single connectivity service to reduce redundant work and delegate contention. [AppContainer.swift](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Application/AppContainer.swift#L71-L75), [VpnViewModel.swift](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/Network/VPN/ViewModels/VpnViewModel.swift#L74-L85), [WifiMonitor.swift](https://github.com/jackson-storm/DynamicNotch/blob/f8623de5806ec5a22d9845189360bc9f4d92c374/DynamicNotch/Features/Network/WiFi/Services/WifiMonitor.swift#L40-L51).
- Download scans use file notifications plus a 1 s fallback timer while tracked files are active. Feature modules present include battery, Bluetooth, calendar, downloads, AirDrop/file tray, external devices, Focus, HUDs, lock-screen panels, Wi-Fi/VPN/hotspot, notch/capsule, media/lyrics/equalizer, screen recording/screenshot hub, timers, settings, software update, and webcam unlock. Broad searches did not identify dedicated CPU/GPU/RAM/network/disk-statistics, clipboard-history, or color-picker modules comparable to Atoll; verify any claimed parity before choosing a full fork. This is a source inventory, not proof that every feature works or every advertised external-app event is detectable.

Recommended adoption gate: remove DN-01; fix DN-02/DN-03; remove upstream updater authority; disable external lookups by default; reduce feature permissions and local logging; split shared service state from per-display windows; audit dependency/framework provenance before any future build. These are implementation recommendations, not changes made by this review.
